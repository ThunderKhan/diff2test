# STDLIB.md Submission Outline

## Purpose

Explain what packages would normally be used and how diff2test replaces them with code written during the event using permitted C++/libc/POSIX facilities.

## Rule boundary and disclosure

- CMake, CTest, Git, and compiler may produce input outside diff2test.
- diff2test never invokes them at runtime.
- File API JSON, `.d`, and CTest JSON are disclosed external data formats.
- Build tool and dev-only test tooling are identified separately.
- No vendored third-party source ships.

### CMake is tooling, not a runtime dependency

State this explicitly and cite the organizer clarification:

- CMake is permitted as the project build system.
- The compiler and build tool are explicitly not counted against the zero-runtime-dependency rule.
- CMake/CTest may generate metadata outside the `diff2test` process; that metadata is later parsed as ordinary input data.
- The `diff2test` executable never launches CMake, CTest, Git, a compiler, shell, or any other external executable.
- The runtime artifact contains no CMake library/package and does not need CMake to be running.
- Missing CMake/CTest-generated metadata must trigger conservative degradation rather than automatic tool invocation.

Use precise wording: **CMake is permitted external build/input-generation tooling, not a third-party runtime dependency of `diff2test`.** Do not imply that CMake is part of the C++ standard library.
